# 手绘视频总控 · 分镜体系 v3.8

安装或判断可制作能力时先读[安装与依赖](references/installation_and_dependencies.md)。代码与必要资源随包提供；Python、FFmpeg、浏览器、Node.js、剪映和生成服务按路线另行准备。不读取开发者本机工具或私有案例目录。

先阅读 [分镜工程指南](references/shot_video_guide.md)、[制作阶段](references/production_stages.md) 和 [素材契约](references/frame_and_asset_contract.md)。知识与教程任务同时使用 [知识导演](../knowledge-video-director/SKILL.md)。

## 先选输出路线

方案设计前明确用户需要浏览器渲染的MP4，还是用户用剪映导出的草稿。未明确时先介绍这两个选项并询问，不默认替用户选择；新建CLI必须填写--output-target。

- web：[浏览器制作Skill](../handraw-browser-producer/SKILL.md)，可按实际实现选择七类分镜，制作程序动画并输出MP4。
- jianying：[剪映制作Skill](../handraw-jianying-producer/SKILL.md)，默认限ST-001～004且检查具体原生配置，输出草稿＋素材包，由用户在剪映导出。

**剪映草稿箱前置检查要求**：当用户选择剪映路线或提示词中包含“渲染方式：剪映”时，Skill 必须先检查用户是否已配置剪映草稿箱路径（检查 `hvp jianying-config` 状态）；若用户从未填写过剪映草稿箱文件夹位置，必须先主动询问用户并获取草稿箱绝对路径（提示用户在剪映全局设置中查看并告知，保存至本机配置），不得在未获取草稿箱路径时推进后续方案确认与草稿交付。

脚本、风格、配色、Flow任务、方案确认、素材审查、配音及字幕共用本总控流程。输出路线进入完整方案，不等到合成时才检查；剪映不支持的配置不得自动转网页预渲染。具体镜头预渲染需要真实用户同意与当前方案签名，见[剪映规则](references/jianying_output_guide.md)。

## 唯一分类

用 `hvp catalog --kind shot` 读取 `catalog/shots.json`。共享目录仅七类：ST-001 单图动画、ST-002 视频、ST-003 背景＋透明素材动画、ST-004 全图有限帧动画、ST-005 Remotion 动画、ST-006 simo 版白板动画、ST-007 SRT 版白板动画。

每镜选择一个主类型，内部可用多个图层。AI 根据需求设计受众、目标、脚本、全片视觉与运动方向，再逐镜选择类型。画风、图型、配色为共同视觉设置；字幕、声音、衔接和输出方式为共享设置。不得用业务名称选择实现。

ST-001 单图动画只列全屏模式与绘本模式：前者以完整主图组织全屏画面，后者使用背景、插画区与文字区。关键帧动画和环境特效均可选；环境特效按具体实现检查，不默认添加。这两种模式仅归于ST-001，不新增版式画廊或其他模式目录。

## 绘本视频请求

用户说“做绘本类视频”“动态绘本”“有声绘本”时，必须读取[绘本制作指南](references/picturebook_guide.md)，按ST-001绘本模式设计多页故事，浏览器与剪映两条路线都可采用。默认参考《一片叶子的屋檐》的阅读布局：纸页留白、完整插画居中、短句在插画下方、小标题可选；不默认做左右图文解释栏。参考的是布局与阅读节奏，故事、角色、画风和色板按本期需求设计，不固定复用刺猬或水彩风格。

先确认输出路线，再提交包含每页事件、插画、短句、口播、页面区间和衔接的完整方案。未指定图型时默认每页一张无字完整插画，标题/短句/字幕分层；指定图型时按手绘出图规则生成完整图文页，不擅自拆分。多页使用多个ST-001镜头，不把翻页归为ST-004角色动作序列。剪映按原生关键帧与文字制作草稿，浏览器按确定性时间接口制作MP4；可选环境效果必须服从各路线能力及已确认方案。使用同一素材契约，不因输出剪映要求用户先生成整段绘本视频。

七类不足时，可在本期 `local_types` 写独立类型、素材契约和 HTML 实现。先完成技术验证与实际审片，由用户决定是否收录共享库；新增名称不等于新增能力。

## 阶段门槛

**调研与方案 → 用户确认 → 画面素材准备 → 全部画面素材审查通过 → 配音与动画 → 合成 → 验收。**

“帮我做视频”仅授权方案阶段。完整方案包含受众、目标、依据、标题、脚本、预计时长、视觉与运动方向、逐镜目的/帧区间/动作/类型/来源、素材责任、声音和交付。确认前可盘点已有素材；不得生成画面、配音、动画代码或预演。

确认后可准备插画、参考图、录屏及外部生成提示词。全部必需图片、录屏、视频、图表数据、动作素材经技术检查与实际画面审查通过前，不生成配音、不编写本期动画、不预渲染或合成。子工程同样执行。详见 [阶段记录](references/production_stages.md)。

## 分镜素材准备与补齐

所有视频图片提示词与出图沿用[手绘出图规则](references/image_prompt_rules.md)。用户指定图型时，完整执行原图型与图文模式规则；不因视频用途擅自改成无字插画＋后期文字。已生成的完整图文卡不重复叠加同文案，图内文字的不可编辑性与独立字幕分别说明。

按本期使用的ST编号读取[分镜素材准备目录](references/shot-materials/README.md)及对应独立文档；`catalog/shots.json`的`material_guide`指向该文档。逐镜盘点所需素材、具体格式、尺寸、透明要求、已有文件与缺项，区分前置画面输入和制作阶段产物。

方案确认后，每个缺失且可生成的素材都必须交付本镜完整、可复制的提示词，并保存到本期`work/material-prompts/`；同时给出素材编号、文件名、格式、实际参考图、回传位置和审查点。不能仅交付泛用模板或让用户自行找图。参考图缺失时先建立参考图任务，审查通过后再生成相关动作帧。真实录屏、事实数据、用户原件及实际字幕时间缺失时，提供采集或补充要求，不能用生成内容冒充。全部输入审查通过后才进入配音与动画制作。

## 素材策略与外部视频

`auto` 可含零视频；`no_video` 禁止视频画面输入；`video_only` 每镜主画面来自原速视频，可添加文字/声音/字幕。内部镜头缓存不是外部视频输入，也不绕过策略。操作教程使用真实录屏作为操作证据；生成视频仅做示意或叙事。

有 Flow 或其他平台生成任务时，交付 [独立提示词与参考图任务包](references/external_video_workflow.md)，等待用户回传。保存版本、候选、哈希、审看与选用记录。未回传、过短、损坏、身份/动作/衔接不合格均阻止制作。不循环、冻结或变速凑时长。

## 实现与输出

新工程仅 `composition-v2`。`episode.json` 为全片方案，`composition.json` 为 `shots`。旧工程、成片与原始素材保留，不执行、不转换。

`new / validate / render / build / export-plan / export` 使用同一模型。`export` 使用已准备声音，不调用配音。`build` 可按明确配音设置执行，但指定服务不可静默替换。火山引擎使用随包[火山语音Skill](../handraw-volc-tts/SKILL.md)，`hvp tts`按provider分派并生成实际字幕时间。`hvp volc-config`保存用户提交的账户，`hvp volc-status`仅查看配置状态；密钥在仓库外用户目录保存，更新Skill不覆盖。

每帧由帧号复算。网页实现保留 `renderFrame(t)`；CSS 动画暂停并定位，JS 不依赖墙钟。Remotion 与有状态白板逐镜生成内容寻址缓存，再解码逐帧合成。SRT 白板先审核线稿与输入数据；没有 SRT 时审核通过后配音，再用真实字幕对齐，不猜时间。

[剪映规则](references/jianying_output_guide.md)：全片输出与逐镜实现分别记录，但须服从已选路线。默认剪映原生；不能原生时阻止并报告，不自动预渲染。用户同意具体镜头后才可按镜生成视频缓存；明确原生要求仍不可回退。不强行改写效果。

剪映交付使用内置pyJianYingDraft和已吸收的剪映编辑方法，不读取外部参考项目。包内离线检查器与安装器仅依赖Python标准库；所有播放素材实际打包、重绑定检查后才安装。`hvp jianying-check <包或草稿目录>`检查文件、引用、时间和路径；`hvp jianying-resources <关键词> --kind transition|filter|effect|character_effect|intro|outro`检索名称及真实ID，不自动选用或下载。方案选定的转场/特效/滤镜在shot.jianying记录并自动写入草稿；支持范围、参数和转场作用域见剪映指南。原生效果改版参与方案签名，需重新确认。

用户可用hvp jianying-config --draft-dir "目录"保存本机剪映草稿箱。配置在用户目录而非仓库，更新与Skill同步不覆盖。安装默认使用保存值，--draft-dir只覆盖本次；不把用户路径硬编码到共享Skill或分发到交付包。

## 证据与交付

交付或修正预览/草稿时读取[镜头审查与交付核对](references/delivery_review.md)。核对用户指定的实际案例版本，区分原图、整页和截图；按可编辑对象分轨，同一sprite的动作帧合在一条轨道。预览、实际草稿、安装包和说明分别更新并检查。截图受限或软件未审看时如实列待验项，不能用坐标/哈希/JSON通过代替视觉通过。

目录状态必须指向实际验证证据。技术验证、应用打开/导出、用户审美接受分别记录。交付 MP4/草稿、预览、字幕、封面、关键帧、工程和制作记录。分镜画廊仅展示编号、PNG截图、分镜介绍和渲染方式，卡片与弹窗不写实测案例、不加载视频；不把编辑代理当实际笔迹。Skill安装只带截图，排除演示视频与私有期工程素材，不按验证记录下载视频。详见 [验证记录](references/validation.md)、[来源许可](references/source_licenses.md)。
