# 镜头审查与交付核对

用于本期预览、剪映草稿交付及用户反馈后的修正。保持既有方案确认和画面素材审查门槛；本文件补充实际核对方法，不新增分类或制作入口。

## 1. 先看用户指定的实际案例

用户指定案例时，读取它实际使用的版本、原始素材和可见画面，区分原始无字插画、已排版整页图片、预览截图与成片。不能只看目录名或文字说明就宣称风格已匹配。

- “参考这种样式”：提取页面比例、插画与文字位置、留白、质感和节奏。本期故事、角色、素材另行设计；不要把绘本误做成左右解释栏，也不固定照搬参考案例的主题。
- “直接用这些图片/这张整页”：盘点实际文件，明确选用哪个版本与用途。复制原件并核对哈希；草稿打包可能重新编码图片，此时比较解码后的尺寸和像素。不得换一张近似素材仍说用了原图。
- 默认可编辑图文使用无字插画＋独立文字。已排版整页图片可以在用户明确选择后作为单图使用，须说明标题、短句等已在图内，不能独立编辑。整页图片中的人物和文字不自动被称为独立sprite或原生文字轨道。

绘本细节见[绘本指南](picturebook_guide.md)。记录选用文件、原始来源、复制/处理方式、审看结果和编辑限制；不要把某次整页复用变成所有绘本默认烘焙文字的规则。

## 2. 剪映时间线要按对象可读、可编辑

核对实际导出的draft JSON及editing-map.json，不只核对composition.json的意图。

|对象|轨道组织|实际检查|
|---|---|---|
|背景/纸底|与角色和文字独立；无转场连接的背景按镜头组织|背景片段所在track ID与角色、文字不同|
|每个sprite|一个对象一条轨道；静态、循环和非循环都适用|同一sprite全部动作帧属于同一track ID，不是每帧各建一轨|
|动画帧|在该sprite轨道按明确显示时段排列|相邻帧边界正确，无意外重叠、空隙；循环周期和非循环末帧保持/隐藏符合配置|
|多个sprite|各自独立，保持遮挡顺序|角色/道具分别可选，render_index及前后关系正确|
|全图有限帧|同一主画面轨道内顺序切换|不拆人物和背景，不每张图新增轨道；停留时间精确覆盖镜头|
|标题、说明、字幕|与图片、sprite和背景分开；同时显示且需分别编辑的文字独立|实际material为text，字幕不烘焙进角色或背景|
|旁白、音乐、音效|按显式音轨分开|时段、截取、音量和淡出配置正确|

原生转场需要相邻主画面同轨时，仅把参与转场的主画面放入hvp_primary；ST-003为背景，角色和文字仍独立。不能为了转场把整镜压成图片/视频，也不为没有转场连接的镜头强制共用主画面轨道。明确获准预渲染的镜头例外须说明画面层已合并。

交付轨道名称、内容角色、片段数量、时间范围及共享主画面的原因。不要声称轨道已经混合或已经分开而不检查实际track ID；即使底层分开，过多碎片轨道或不清楚的命名也需要整理。

## 3. 预览必须说明展示的是什么

预览页、画廊卡片和安装草稿分别核对，不能认为修改一个文件其他输出就自动更新。

1. 素材卡片展示单张原图时标明“素材”。若展示整页布局，应使用实际整页图/截图或明确标记的布局示意，不能拿裸插画代表完整绘本页。
2. 静态HTML/CSS示意不等于剪映实际画面。说明其用途，避免与“成片预览”混淆；存在实际输出截图时优先用实际截图。复制的完整原页也仅证明该图片内容，不证明草稿已在剪映正常显示。
3. 用户要求截图或指出画面不对时，尝试查看实际页面/结果并保留证据。工具拒绝访问或截图失败时，记录具体限制，不能以文件存在、坐标正确或哈希一致代替视觉审查。不得通过换协议、换浏览器或其他方式绕过工具明确禁止的访问。
4. 无法取得当前页面截图时，可以继续检查本地原图、引用、尺寸和草稿结构，但必须标记“页面视觉未核验”；动态效果及剪映应用审看仍待实际验证。
5. 检查预览指向的新素材、新包名、新草稿名；避免用户刷新后仍看到旧图、旧下载链接或旧说明。源文件更新后保留必要的版本标识。

可编辑图文排版要检查实际文字宽度、字体、换行、图像边界及字幕面板遮挡。归一化坐标和CSS字体计算只作为实现参数，不能单独证明构图正确。原生文字在剪映实际打开后还需检查字体与显示位置。

## 4. 修正后一起更新交付

用户指出错误时，先定位具体文件/轨道/素材并修正。用户明确提出的修改授权覆盖对应修正范围，保存真实回复和版本记录；如改变方案内容，更新方案及确认记录，不伪造另一次“确认”，也不因已有记录而重复询问同一个已授权修正。

保留旧原件、工程记录、交付包和安装草稿。新草稿使用唯一名称，禁止覆盖用户在剪映中编辑的旧版本。依次更新本期工程、实际输出、包与安装检查、editing-map、预览引用、README、验证记录及episode.delivery；共享缺陷修复后同步实际加载的.agents/skills并核对哈希。

改动渲染/导出代码时，用有意义的回归检查验证具体风险：例如至少一个循环和一个非循环sprite，确认背景、角色、文字track ID不同，各角色帧合轨且时间连续，末帧策略保留，转场引用和遮挡顺序正确。规范文字修改检查引用、前后规则和安装副本一致性；不为文档更新重做旧成片或调用付费服务。

## 5. 完成状态与证据

制作记录分别填写以下状态及证据路径：

- 原素材实际审看与复制/像素核对。
- 当前预览页面截图审看；未取得时填写未验证及限制。
- 草稿结构、轨道、素材引用与安装路径检查。
- 剪映实际打开、关键时刻视觉/轨道审看。
- 实际MP4导出、完整解码、帧数/时长、声音检查。
- 用户审美接受。

完成技术检查可以交付带明确待验项的草稿包；不能把JSON检查、数学居中、像素一致、测试通过或已安装写成“应用视觉通过”“已截图确认”或“成片已验收”。反馈仍指出画面错误时继续修正，不仅解释为什么旧方案理论上正确。
