# ST-003 · 背景＋透明素材动画：素材准备

先执行[共用缺素材规则](README.md)。每个透明主体独立选择静态、有限帧循环、有限帧非循环；不限制只动局部。

## 所需素材与格式

|素材|必要性|交付格式|要求|
|---|---|---|---|
|背景图|必需|优先PNG；可解码JPG/WebP|完整场景，预留主体运动/接触空间；不要把需独立表演的角色画死在背景中|
|静态主体|选择static时必需|真实RGBA透明PNG一张|轮廓完整、无白边黑边、无棋盘格|
|循环动作帧|选择loop时必需|同尺寸RGBA PNG序列|连续循环、首尾接近；明确每帧停留时间|
|一次性动作帧|选择once时必需|同尺寸RGBA PNG序列|准备→执行→接触→结果→反应；不要求末帧回到起点|
|身份参考|多帧/跨镜头需要时|实际PNG参考|同一脸型、衣服、配件、比例、视角和光照|
|道具/前景遮挡物|需要独立交接/遮挡时|独立透明PNG及必要动作帧|手部接触、持有/飞行/落地层交接明确|
|动作/运动记录|必需说明；已有文件作为输入盘点|JSON或MD说明，最终写入config|显示区间、播放方式、帧顺序、脚底/手部/接触锚点、z_index、规律运动参数|

动作帧使用固定画布大小与锚点；不要每帧自动贴边裁切，否则会抖动。多主体可同时/依次出场。文字、矢量、特效为可选图层，不自动要求生成。

## 文件与配置

推荐`assets/S03/background.png`、`hero-reference.png`、`hero-loop-01.png`等。四秒/30fps示例：

```json
{
  "background": "assets/S03/background.png",
  "sprites": [
    {
      "id": "hero",
      "playback": "loop",
      "frames": [
        {"asset": "assets/S03/hero-loop-01.png", "hold_frames": 8},
        {"asset": "assets/S03/hero-loop-02.png", "hold_frames": 8}
      ],
      "region": [0.1, 0.2, 0.3, 0.6],
      "start_frame": 0,
      "end_frame": 120,
      "contact_anchors": {"foot": [0.5, 0.95]},
      "z_index": 1
    }
  ]
}
```

static用asset，不加frames；once用frames，结束默认保持最后帧，需消失时on_end=hide。有规律运动另记录motion规则、参数和起止帧；PNG本身无需预先画出整个轨迹。

## 缺素材提示词

按缺项分别生成任务，不把角色和背景合成一张图交来后宣称可拆层：

```text
背景图：生成{尺寸}的{本期画风与色板}场景。地点{具体环境}，视角{透视/景别}，光线{方向}。在{主体位置和路径}预留可活动区域，画清{地面/接触物体/前后景}。不出现{需独立生成的角色和道具}，不加文字或水印。主体将以{实际参考比例}进入画面，因此{空间与遮挡要求}。
```

```text
透明主体第{编号}/{总数}帧：依据实际提供的{身份参考图}绘制同一{完整身份、服饰、道具}。输出{统一像素尺寸}的真实RGBA透明PNG，只包含{主体及明确附属物}。画风/透视/光照与{背景参考}一致。固定{脚底坐标、身体基准、缩放和画布余量}；本帧动作是{具体姿态、手脚和接触点}。仅改变{本帧应变部分}，保持其他身份特征。不要背景、棋盘格、投影底板、文字、裁断手脚、额外肢体或帧间尺寸漂移。
```

先输出各帧动作表，再为每帧写独立提示词；不能只写“做一个循环动画”。loop说明最后到第一帧如何衔接；once写清动作阶段及最终hold/hide。缺道具或遮挡前景也各给一个透明素材提示词，明确同一光照与接触尺寸。

## 验收与输出路线

- 审查实际alpha、帧间身份、锚点/足底、边缘与遮挡。接触后再出现反馈，背景横移不能证明角色行动。
- 序列必须真实存在；目录中文件名排序不代替frames与hold_frames记录。
- 剪映可用基本图层、帧序列和已适配关键帧；有规律运动/JS效果需逐项检查，不能直接宣称原生。当前原生主画面转场只作用于背景，角色和文字不随它转场。
